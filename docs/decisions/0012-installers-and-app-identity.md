# 0012 — Installers (makers), icon, version information and About

- **Status:** accepted
- **Date:** 2026-10-15
- **Feature:** S28.1

## Context

PLAN §5 asks for direct-download installers built on each target OS: a DMG for Apple Silicon and an installer for
Windows x64, with manual upgrades that keep projects and settings (PLAN §11). Electron Forge 8 is the packaging tool
(ADR 0004); S02.1 already configured the Squirrel, DMG and ZIP makers with defaults. S28.1 has to choose the Windows
installer technology on purpose, give the app its own icon and version information, and show the version in an About
dialog. Signing is separate (S28.2 / S28.3, blocked on owner task H.2).

## Options considered

**Windows installer**

| Option                                   | For                                                                                                                                                                              | Against                                                                                                                                                                                                                                          |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Squirrel.Windows** (`maker-squirrel`)  | Already in the build and in the S02.7 check; per-user install without admin rights (good for school/lab PCs); running a newer `Setup.exe` upgrades in place; pure npm dependency | Fixed install location (`%LOCALAPPDATA%\NoobIDE`); Programs-and-Features icon comes from an install-time **https** `iconUrl`; the first launch after install comes from Squirrel's `--squirrel-*` events (handled in `src/platform/squirrel.ts`) |
| WiX MSI (`maker-wix`)                    | Familiar MSI, per-machine installs, chosen location                                                                                                                              | Needs the WiX Toolset installed on the build machine (native tool outside npm); usually needs admin rights; upgrade codes must be managed by hand                                                                                                |
| MSIX / AppX (`maker-appx`, `maker-msix`) | Modern packaging, clean uninstall                                                                                                                                                | Must be signed to install at all (blocked on H.2); sandboxed file-system virtualisation complicates "project folders stay ordinary" and app-data locations                                                                                       |
| NSIS via electron-builder                | Flexible installer UI                                                                                                                                                            | A second packaging tool next to Forge (ADR 0004 chose Forge)                                                                                                                                                                                     |

**macOS:** DMG (`maker-dmg`, ULFO compression) built on an Apple Silicon Mac for arm64, plus a ZIP. A PKG installer
brings nothing for a single drag-to-Applications app.

**Icon:** no artwork exists yet. Options: wait for the owner, or generate a clearly placeholder icon so every build
has a real app icon now. Image tools (ImageMagick, `iconutil`, `png2icons`) would add a native or platform-only
dependency.

**Version in About:** read `app.getVersion()` over a new IPC channel, or inline package.json's `version` into the
renderer at build time.

## Decision

- **Windows: Squirrel.Windows**, `NoobIDE-Setup.exe`, per-user, `setupIcon` = the app icon. `iconUrl` stays the
  Electron default (an https URL fetched at install time; Squirrel does not accept `file:` URLs) until a public
  release download host exists — then set it to that host's `icon.ico`. Without network at install time Windows
  simply shows a generic icon there; installation is not affected.
- **macOS: DMG (ULFO) + ZIP**, arm64 when built on Apple Silicon; the DMG window shows the app icon.
- **Icon:** placeholder artwork (green rounded square with a white `</>`) generated by `scripts/make-icons.mjs` in pure
  Node (zlib only, deterministic) into `resources/icons/` as `icon.png` (1024), `icon.icns` (PNG entries 16–1024)
  and `icon.ico` (PNG entries 16–256). The generated files are committed, so builds need no image tools. Replacing
  the artwork = overwriting the three files with the same names and sizes.
- **Version information:** package.json `version` is the single source. Electron Packager writes it to
  `CFBundleShortVersionString` / `CFBundleVersion` and the Windows `FileVersion` / `ProductVersion`; `forge.config.ts`
  adds `win32metadata` (CompanyName, ProductName, FileDescription, InternalName, OriginalFilename), `appCopyright`
  and the macOS category `public.app-category.developer-tools`. The copyright holder text is a placeholder for the
  owner to confirm.
- **About:** a React dialog (`src/renderer/workbench/AboutDialog.tsx`), translated (zh-CN, en), showing the version
  inlined at build time by `vite.renderer.config.ts` (`__NOOBIDE_VERSION__`, the same package.json value
  `app.getVersion()` returns — no new IPC surface) and the Electron / Chromium versions from the user agent. Its
  description claims only proven capabilities (editing and previewing HTML / CSS / JavaScript). It opens through
  `openAbout()` (`src/renderer/workbench/about.ts`); the menu entry belongs to the S24 command registry / menus.

## Consequences (incl. how it is verified on macOS arm64 and Windows x64)

- `tests/integration/distribution.test.ts` checks the maker/platform mapping, that every referenced icon file is
  bundled and well-formed (ICO/ICNS directory entries are PNGs of the declared sizes), the version metadata and that
  the renderer is built with package.json's version.
- `tests/e2e/distribution.spec.ts` checks the packaged app on the platform it runs on: on macOS the `.app` is arm64
  (on Apple Silicon), its `Info.plist` carries the package.json version, the bundle id, the category and `icon.icns`;
  on Windows the executable exists next to the icon resources. It also opens About in the app and reads the version.
- `npm run make` on an Apple Silicon Mac produces `out/make/NoobIDE-<version>-arm64.dmg` (checked during S28.1);
  the Windows installer has to be built and installed on Windows — steps in `harness/MANUAL-CHECKS.md#S28.1`.
- Until S28.2/S28.3, installers are unsigned: macOS Gatekeeper and Windows SmartScreen warn on first launch.
