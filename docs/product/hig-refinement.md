# HIG refinement (S44)

Owner request, 2026-10-15 (scheduled run): refine the UI following Apple's
[Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) — neat, simple,
easy to use, clean and clear. **Where the HIG and an earlier project rationale disagree, the HIG wins.** This document
is the S44.1 audit: what was wrong per screen, which HIG area applies, what changed, and which earlier decisions were
overridden. It builds on the Liquid Glass study ([liquid-glass-study.md](liquid-glass-study.md), decision 0029), which
already paraphrases the HIG pages on materials, controls and motion; S44 is about layout and information density.

Method: the S40.7 `glass-visual` spec captured the shell at 1280×800 in light and dark (welcome, workbench, menu,
problems, palette, AI, sheet). Each screen was read against the HIG pages for Toolbars, Menus, Layout, Onboarding,
Sidebars, Buttons, Segmented controls, Toggles, Pop-up buttons, Sheets and Accessibility. Five areas were then refined
in parallel (S44.2–S44.6) and re-captured.

## Earlier rationale overridden by the HIG

- **S15.4** (every preview control visible) → More menu. _Toolbars._
- **S15.3** (permanent "not phone emulation" row) → tooltip, accessible description and a one-time note. _Layout:
  progressive disclosure._ The disclosure itself is kept (honesty about what Phone width means).
- **S41.5** (annotations strip and helper sentence always visible) → hidden until there is an annotation. _Progressive
  disclosure._
- **S20.2 / S20** (welcome card above an always-visible sample editor) → focused welcome, sample behind a disclosure.
  _Onboarding, Layout, Disclosure controls._
- **S30.3** (Files / Problems always in the rail, toggle-files always enabled) → hidden or disabled without a project.
  _Menus: disable items that don't apply._
- **S30 / S40.3** (path line and reveal-in-folder button in the top bar) and **S02.5** (language button in the top
  bar) → tooltip and menu. _Toolbars, Windows._
- **S24.1 / S32 / S33** ("show or hide" titles) → state-aware titles. _Menus._
- **S09.3** (font size control in the editor header) → View menu, palette, shortcuts. _Toolbars._
- **S20.3** (file-role hint as its own row) → secondary text in the header row; tree tags unchanged. _Layout._
- **Segmented selection colour** — the selected width option no longer uses the accent fill (raised knob + bold text),
  so the accent marks only the primary action. _Segmented controls, Buttons._

Unchanged on purpose: words next to icons in the rail and toolbars (beginners; PLAN), not-colour-alone state, zh-CN
default + en, the native preview constraint (menus over the preview column hide the view), and the S40 material rules.

## Earlier rationale overridden by the HIG (S45)

- **S44.5** role hint as label + sentence → short tag; **S44.5** always-labelled History / Format → icon-only when the tabs need room.
- **S11.2 / S11.3 / S13.x** long notice copy and "keep mine (overwrite…)" as the visible label → title + one sentence, details in tooltips.
- **S44.2** narrow preview drops its title first → the width control gives way instead.
- **S14.4** full consent explanation inline → one sentence + "Why?" disclosure (same honest wording).
- **S17.1** "None" under empty problem sections → 0 badge.
- **S21.3 / S21.4** history storage always visible → disclosure. **S12.2 / S12.3** question-style confirm labels → verbs.
- **S20.2** numbered wizard steps and preview picture → short labels and a summary; welcome copy shortened; **S44.3** 2:3 centring → 5:6.
- **S08.3** accent "Move to Trash" → destructive style.
- **S44.6** visible Ask/Edit hint and three add buttons → tooltip / accessible description and one Add (+) menu.
- **S33.1** consent inline above the composer → the panel's empty state until answered (nothing is sent before it).
- **S39.1** separate Open button per saved chat → the row opens it.
- **S40.3** rail inner ring → fill + bold.

## Left open

- `AiSettingsDialog` is still hand-built (listed as the one exception in `Sheet.test.ts`); move it onto `<Sheet>`.
- With no key, the AI composer stays visible (Send disabled) so a draft survives key setup; hiding it would be calmer.
- S44.6 switch/checkbox `:disabled` still use opacity 0.6 (not a text-contrast failure).
