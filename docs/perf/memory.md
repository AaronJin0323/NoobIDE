# Memory — breakdown, reductions and remaining options (macOS arm64)

Device: Apple M3 Pro, 18 GB RAM, Darwin 27.2.0, Electron 44.7.0 — **not** the 8 GB reference machine of PLAN §11.
Decision record: [0024-memory-budget](../decisions/0024-memory-budget.md). Budget rows of the §11 table:
[darwin-arm64.md](darwin-arm64.md) (generated by `scripts/measure-perf.mjs --write`).

## How it is measured

`node scripts/measure-memory.mjs [--runs 3] [--idle-ms 30000]` after `npm run package`. Production bundles on the
unpackaged binary (Playwright cannot attach to the packaged one), fresh app-data directory per run, 30 s idle before
the sample, median of 3 runs. `--packaged` measures the packaged binary's idle state without automation.

Two numbers per process:

- **ws** — `app.getAppMetrics()` working set, what `measure-perf.mjs` sums for the budget. Counts shared pages (the
  Electron framework, mapped by every process) once per process, so the sum is an **upper bound**; and it does not
  include the GPU process's graphics memory.
- **fp** — macOS `phys_footprint` (`footprint` tool; Activity Monitor's "Memory"): private dirty + compressed memory +
  IOKit/GPU memory attributed to the process. The closer estimate of what the app costs the machine. On Windows the
  scripts use `privateBytes` instead.

Scenarios: **idle** — welcome screen, editor focused (a character typed), nothing else. **preview** — the default
built-in template (personal-intro) open, `index.html` in the editor, preview running. **files10** — a 10-file project
(4 HTML, 3 CSS, 3 JS, 6–14 KB each), all ten open in tabs, preview running.

## Where the memory goes

- **GPU process: depends on whether frames are being drawn.** ~300 MB for the first seconds after start, ~45 MB once
  nothing is drawn, ~175 MB while anything redraws regularly. Monaco's blinking caret (a frame every 0.5 s while the
  editor has focus) kept it at ~175 MB indefinitely. Its working set (~70 MB) does not show this memory at all.
- **Monaco language workers** (threads in the workbench renderer): the TypeScript worker (JavaScript diagnostics,
  completion, hover; ES + DOM type libraries) costs **~83 MB** as soon as a `.js` file is open (219 → 136 MB renderer
  footprint when it is terminated). HTML + editor workers ~12 MB. Monaco stops idle HTML/CSS/JSON workers after 2 min
  and the editor worker after 5 min, but never the TypeScript worker.
- **Workbench renderer** without workers ~100 MB (Chromium/Blink baseline, React, Monaco; the V8 heap of the page is
  ~26 MB).
- **Main process** ~50 MB (~66 MB packaged), **network service** ~7 MB, **preview renderer** ~25 MB for the template.

## Tried and not taken (numbers: renderer or GPU footprint)

| Experiment                                      | Result                                               | Why not                                                                                               |
| ----------------------------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Monaco `disableLayerHinting: true`              | GPU unchanged (~185 after typing)                    | no effect                                                                                             |
| `--force-gpu-mem-available-mb=128`              | GPU unchanged                                        | no effect                                                                                             |
| `--js-flags=--optimize-for-size`                | idle renderer 102 → 97; with a JS file 223 → 196     | slower JS in the IDE and in the user's page for a small gain                                          |
| `--js-flags=--max-semi-space-size=2`            | idle unchanged; with a JS file 223/230/224 → 200/202 | more GC work in every renderer, including the user's page; first option if a reference machine misses |
| Stop the TypeScript worker when idle            | would free ~83 MB                                    | Monaco re-validates every open JS model when its worker is restarted; needs a Monaco patch            |
| Network service in-process / `--in-process-gpu` | one process less each                                | removes a process/sandbox boundary — never trade isolation for memory                                 |

## Remaining gap and options

On this Mac the PLAN §11 scenarios are within the ~700 MB budget by both measures (working-set sum max 577 MB;
private sum ~205–267 MB). The heavier **files10** case (several JS files open) reaches a working-set sum of
544–671 MB (private ~425 MB), driven by the TypeScript worker. Not measured: the 8 GB reference machines and Windows
(the scripts run there unchanged; `privateBytes` replaces the footprint). If a reference machine misses, in order:

1. `--js-flags=--max-semi-space-size=2` (≈ −25 MB with JS open; GC CPU cost to be measured on the reference machine);
2. an idle stop for the TypeScript worker (≈ −83 MB after the idle period; requires patching or replacing Monaco's
   TS worker manager so a restart re-syncs models lazily).
