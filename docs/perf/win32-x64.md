# Performance — win32-x64 (S27.1)

Generated by `node scripts/measure-perf.mjs --write` on 2026-10-15. Definitions are in the header of
`scripts/measure-perf.mjs`. PLAN §11 targets: cold start p95 ≤ 5 s to an interactive editor on a fixed 8 GB reference
machine; update after saving p95 ≤ 1 s for ≤ 50 files of ≤ 200 KB; memory recorded per platform against a ~700 MB
budget (a baseline, not a claim). "Within target" below applies to THIS device only; PLAN §11 claims need the fixed
8 GB reference machine of each platform (see docs/perf/targets.md).

**Device:** 13th Gen Intel(R) Core(TM) i9-13900KF, 32 cores, 32 GB RAM — Windows_NT 10.0.26200 (win32-x64), Electron 44.7.0.

**Measured under partial load — not a clean run.** This is the owner's development machine, not the 8 GB reference
machine, and other agent sessions were running Electron e2e suites on it. After waiting about two hours for a quiet
machine, two full runs were taken at 00:07 and 00:19 local time on 2026-10-16 (build from `npm run make` at the
S02.7 commit), with total CPU logged every 5 s. This document is run 1, written unchanged by the script:

- **Cold start (dev binary):** taken at 100 % CPU from another session's e2e suite. The six slow samples
  (1.5–2.2 s) are that load. Run 2's cold-start batch had the machine idle (CPU < 15 %): median 677, p95 1017,
  min 666, max 2001 ms (n=20).
- **Packaged start, save → preview, memory:** CPU at 5–12 % for the whole phase, which is this run alone on 32
  logical cores. In run 2 these phases were under 99 % load from another session. Packaged start was median 720 and
  p95 775 ms, save → preview p95 121 ms, and memory typical median 711 MB, so the memory result is the same under
  load.
