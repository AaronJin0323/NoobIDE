## Verdict

**Conditional pass on macOS arm64; not passed on Windows x64.** The invite-only build is **ready for Mac testers
only, with a documented Terminal step**, and **not available for Windows testers**.

- macOS arm64: all three technical exit criteria pass at `3314de9`, both on this Mac (81 e2e tests across the 12
  relevant specs, 0 failed) and on the CI `macos-14` arm64 runner (run 38675714521: verify 1643 unit/integration
  tests, e2e 214 passed / 2 skipped, make, inspect-arch). The DMG built here verifies, installs, is arm64 throughout
  and launches natively.
- Windows x64: run 38675714521 is the first CI run where `verify` is green on Windows (1634 passed / 10 skipped), but
  e2e failed (161 passed, 9 failed, 44 did not run), so **Make installers was skipped: no Windows installer has ever
  been built** (S02.7 and S28.1 are still manual). Two of the nine failures sit directly on M3 criteria (console
  flood stall, runtime capture count); the S05.5 isolation attacks and S16.3–S16.6 did not run.

**Conditions to turn this into a pass** (each one is checkable):

1. A CI run on main is green on `windows-x64` through e2e, Make installers and Inspect binary architectures, and
   uploads `squirrel.windows/x64/NoobIDE-Setup.exe` (closes the Windows half of criteria 1–3 and S06.1/S06.2).
2. The macOS invite build passes the codesign check: today the ad-hoc signature inherited from the Electron binary
   is **invalid** after packaging (`codesign --verify`: "invalid Info.plist (plist or signature have been
   modified)"). Re-signing ad hoc (`codesign --force --deep --sign -`) makes it "valid on disk" (tested on a copy).
   This belongs to the packaging config (forge `osxSign` with an ad-hoc identity, or a postPackage step) — release
   work, S28.x — and is the difference between "Open Anyway" and a "damaged" message for testers (see
   "Invited-tester instructions").
3. One person installs the DMG on a second Mac from a real download (not this build tree) following the tester
   instructions below, and records the result in `harness/MANUAL-CHECKS.md#S17.4`.

S17.4 therefore stays `needs_manual_check` (steps in `harness/MANUAL-CHECKS.md#S17.4`), not `done`.

## Invited-tester instructions (until S28.2/S28.3 sign the builds)

What a Mac tester must do today (Apple Silicon only; Intel Macs are not supported):

1. Download `NoobIDE-<version>-arm64.dmg`, double-click it, drag **NoobIDE** onto **Applications**, eject the disk image.
2. Because the build is not signed by an Apple developer and its ad-hoc signature does not validate, macOS will
   refuse to open it from Finder. The message is expected to be "NoobIDE is damaged and can't be opened" (invalid
   signature) rather than the usual "cannot verify the developer"; this review saw the refusal through `spctl` /
   `syspolicy_check`, not the dialog itself. Right-click → Open and System Settings → Privacy & Security →
   "Open Anyway" are not expected to work for a damaged-signature app. The working route, verified above:
   open **Terminal** and run

   ```bash
   xattr -dr com.apple.quarantine /Applications/NoobIDE.app
   ```

   then open NoobIDE normally. This removes the download mark from this one app only.

3. Once condition 2 is fixed (valid ad-hoc signature), the Terminal step should no longer be needed: first launch
   shows "Apple could not verify…", then System Settings → Privacy & Security → "Open Anyway" (macOS 15 and later no
   longer offer right-click → Open as a bypass). This must be re-checked on the fixed build.
4. Tell testers what to send back: macOS version, Mac model, whether it opened, and any problem card text.

Windows testers: nothing to install yet. When condition 1 is met, `NoobIDE-Setup.exe` installs per user without an
admin prompt; because it is unsigned, SmartScreen shows "Windows protected your PC" → **More info** → **Run anyway**.
That flow has not been observed by anyone yet (S02.7).

Invitation caveats to state to testers: unsigned builds, no auto-update (S28.4/S28.5 not done), app data at
`~/Library/Application Support/NoobIDE` (macOS) / `%APPDATA%\NoobIDE` (Windows), version shows 0.0.0.

## Risks

1. **Windows evidence lags.** The first green Windows `verify` is from this run; Windows e2e has never passed in CI.
   The M3 code (S14–S17) was rebuilt on the Mac in session 10 and has never passed end to end on Windows.
2. **Console-flood budget on Windows.** 356 ms worker-flood stall on the shared CI runner versus 15–21 ms on Apple
   Silicon. Could be runner noise (2 vCPU) or a real Windows-path cost of the CDP-installed worker guard; needs a run
   on the Windows dev machine before deciding (raise the budget only with a decision record, never silently).
3. **Unsigned distribution.** Signing (S28.2/S28.3) waits on H.2. Until then every tester install depends on a
   Terminal command (Mac) or a SmartScreen bypass (Windows) — friction that will distort first-launch measurements in
   H.6 (PLAN §11 "time to first webpage" starts at first launch).
4. **Cached `console.log` residual** (decision 0016): 1.2–1.5 s main stall per 2 s of bypassed flooding. Documented,
   bounded, but visible to a tester who writes such a page.
