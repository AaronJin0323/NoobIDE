# Clean-machine acceptance checklist (S29.1 Windows x64, S29.2 Apple Silicon)

This is the checklist for the release acceptance runs: **S29.1** on a clean Windows x64 machine and **S29.2** on a
physical Apple Silicon Mac. It is derived from PLAN §2 (beginner journey), §8 (preview isolation), §9 (error
validation scenarios), §11 (acceptance metrics, required failure cases, installation and upgrades), the offline and
IME requirements, and the manual checks in [harness/MANUAL-CHECKS.md](../../harness/MANUAL-CHECKS.md). The automated
proof behind each failure case is in [fault-matrix.md](fault-matrix.md); this list is what a person runs on real
hardware with the **installed release build**, not the repository.

Not part of this checklist: the beginner user studies (H.6, H.7 — use [task-script.md](../product/task-script.md)) and
the performance measurements (S27, `scripts/measure-perf.mjs`). Results here do not mark any feature done by
themselves; S29.x are closed with the session CLI after the run.

## Before you start

**Machine (record in the header table below).**

- Windows: a clean Windows x64 install (VM or spare PC) at the minimum supported version **and** one at the current
  stable version (PLAN §11). Minimum versions are pending owner task H.1 — until then, run on the current stable
  version and write "minimum not decided" in the header.
- Mac: a **physical** Apple Silicon Mac (not a VM, not a CI runner), same rule for OS versions.
- No development tools: check that `node -v` and `git --version` fail in a terminal (on macOS, `git` may offer to
  install the command line tools — cancel that). No Visual Studio / Xcode.
- A Chinese input method available: Windows "Microsoft Pinyin", macOS "Pinyin – Simplified".
- Network on for section A; sections marked **offline** need it off (Wi-Fi off / cable unplugged).

**Build.** Use the release candidate installers exactly as users get them: downloaded through a browser from the
release location (so the OS applies its download quarantine), not copied from `out/`. Record the version and SHA-256.

**Fixture kit.** Some checks need small pages. Create them by hand in a scratch project inside a folder whose path has
Chinese characters and spaces, e.g. `Documents/验收 测试/项目 一` (Windows: `文档\验收 测试\项目 一`). The snippets are
in [Appendix: fixture snippets](#appendix-fixture-snippets).

**Recording.** In each platform column write `pass`, `fail: <what happened>`, or `n/a: <reason>`. A failure in a
**[blocker]** item stops the release (PLAN §11: no known file-loss issues in core workflows; isolation; offline).
Attach screenshots or recordings only as notes — they are not evidence of a pass on their own (PLAN §10).
